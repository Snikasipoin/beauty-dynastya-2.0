# Заявки из формы в Telegram

## Что подключено

Форма отправляет JSON на HTTPS API Bothost, путь `POST /api/applications`. Адрес задаётся публичной переменной сборки `VITE_APPLICATION_API_URL` на Timeweb. Сервер проверяет поля, согласие, версию документа, происхождение запроса и ограничения частоты, затем вызывает Telegram Bot API. Сообщения получают только пользователи из серверного списка `TELEGRAM_ADMIN_IDS`. ID из браузера игнорируются. Успех отображается после подтверждения Telegram для всех настроенных получателей.

Состав заявки сохранён: имя, страна, роль, язык, подтверждение и редакция согласия, время на устройстве и время получения сервером, ссылки на документы, номер заявки. Контакт заявителя текущая форма не запрашивает.

## Бот @beautydynastya_bot

1. Каждый получатель открывает https://t.me/beautydynastya_bot и нажимает «Запустить». Без этого бот не сможет написать ему.
2. Токен от BotFather хранится в секретной переменной `TELEGRAM_BOT_TOKEN`. Локально — в `.env.local`, который исключён из Git и Docker-контекста.
3. В `TELEGRAM_ADMIN_IDS` перечисляются разрешённые числовые Telegram ID через запятую. Это ID пользователей, а не @username и не ID бота. Поддерживается до десяти получателей.
4. При необходимости команда `pnpm telegram:chat` прочитает личные чаты из ожидающих обновлений и покажет ID без вывода токена. Она не отправляет сообщения и не подтверждает обновления. Если используется webhook, получение обновлений этим способом недоступно; удалять чужой webhook команда не будет.

Для локальной разработки:

```sh
pnpm dev:server
pnpm dev
```

Команды запускаются в разных терминалах. Vite проксирует `/api` на порт 3000; локальный `APP_ORIGIN` должен совпадать с фактическим адресом Vite, включая протокол и порт.

## Размещение на Bothost

Сайт остаётся на Timeweb в режиме React. Для обработчика используется оплаченный слот Bothost, тот же репозиторий и отдельная ветка `codex/bothost-bot`. Она содержит готовый JavaScript для Node.js 22, `index.js`, `package.json` без внешних зависимостей и собственный Dockerfile.

[Пошаговая настройка Bothost](bothost-setup.md) описывает поля формы, порт 3000, HTTPS-домен и переменные `TELEGRAM_ADMIN_IDS`, `APP_ORIGIN`, `PORT`, `TRUST_PROXY`. Токен из поля Bothost Bot Token передаётся через `BOT_TOKEN`; обработчик поддерживает также `TELEGRAM_BOT_TOKEN`.

После создания нужен фактически выданный домен Bothost. Значение `VITE_APPLICATION_API_URL` на Timeweb должно содержать этот HTTPS-домен и `/api/applications`. Токен в эту переменную не включается. После изменения адреса пересоберите сайт.

Сервер принимает браузерные запросы только с `APP_ORIGIN`, включая CORS preflight для POST JSON. Предварительный OPTIONS-запрос не отправляет сообщения. Основной домен сайта — `https://beauty-dynastya.com`.

GitHub Pages остаётся статическим предпросмотром. Для отправки с другого домена требуется отдельная явная настройка разрешённого источника; текущая конфигурация разрешает только основной сайт.

## Проверка после настройки

1. Убедиться, что каждый разрешённый пользователь нажал «Запустить» у бота.
2. Открыть рабочий сайт по HTTPS и отправить одну явно тестовую заявку.
3. Проверить получение сообщения каждым получателем и показ успеха на сайте.
4. Проверить ошибку при недоступности API: поля остаются заполненными, успех не показывается.

`GET /api/health` проверяет работу процесса; этот ответ не подтверждает действительность токена или возможность написать получателю.

## Ограничения

- Постоянной базы заявок нет: заявки остаются в сообщениях Telegram. Без настроенного токена, получателей и адреса сервер возвращает недоступность, а не успех.
- Ограничения действуют в памяти одного процесса: пять попыток с одного IP за десять минут и тридцать за минуту суммарно. При нескольких инстансах требуется общий ограничитель.
- В течение десяти минут повтор того же номера не дублирует подтверждённую отправку. При частичной доставке повторяется только отправка оставшимся получателям. Память повторов сбрасывается при перезапуске.
- Если Telegram принял сообщение, но сетевой ответ потерялся, подтвердить доставку сервер не может; повтор в этом случае может создать дубль. Автоматические сетевые повторы не выполняются.
- Сервер не пишет тела заявок и токены в собственные логи. Политики и технические журналы хостинга и Telegram действуют отдельно.
- Документы сайта обновлены под Timeweb → Bothost → Telegram, редакция `2026-11-14.3`. Сохранились запрошенные ранее заглушки реквизитов оператора.
